# ADR 0001: 端侧优先架构

## 状态

已接受

## 背景

类似豆包的产品通常依赖云端大模型获得较强通用能力，但用户对语音、摄像头、屏幕和个人记忆的隐私敏感度很高。同时，手机本地模型的参数规模、内存和发热限制明显。我们需要决定系统的默认执行位置和隐私边界。

## 决策

Edge Assistant 默认采用端侧优先架构：

- 核心推理默认在手机本地执行。
- 音频、图像、屏幕内容和个人记忆默认不上传。
- 云端能力不作为默认兜底；未来若提供，必须显式开关、显式告知和显式授权。
- 产品能力按端侧硬件档位分级，而不是让所有设备尝试运行同一个模型。

## 备选方案

### 方案 A：云端优先

优点：
- 模型能力强，容易做出通用问答体验。
- 端侧工程复杂度低。

缺点：
- 隐私成本高，语音和视频上传压力大。
- 弱网或离线场景不可用。
- 与本产品定位冲突。

### 方案 B：混合云，静默路由

优点：
- 可以在本地模型不够时自动使用云端模型。

缺点：
- 用户难以判断哪些内容会离开设备。
- 隐私承诺变得模糊，不利于建立信任。

### 方案 C：纯端侧，可选显式云端

优点：
- 隐私边界清晰。
- 离线可用。
- 延迟路径可控。

缺点：
- 通用智力弱于云端模型。
- 需要大量工程补偿：模型分级、RAG、工具调用、受约束解码。

## 结果

选择方案 C。

### 正面影响

- 隐私承诺清晰，可用抓包验证。
- 弱网环境可用。
- 语音和视觉链路延迟可控。

### 负面影响与缓解

- 小模型能力有限：通过场景收窄、本地 RAG、工具调用和短回复约束缓解。
- 安装包体积大：通过机型分级和平台资产分发缓解。
- 发热和耗电：通过档位选择、动态降帧、低功耗模式缓解。
