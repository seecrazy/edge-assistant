# ADR 0014: 分层 Agent 记忆、生命周期与混合召回

## 状态

已接受（IOS-18 第一阶段）

## 背景

IOS-15 已交付 AES-GCM 加密 SQLite，但记忆仍是单个平铺 `facts` 数组：所有提取结果直接进入召回，没有待确认状态；召回只做简单字符串匹配，没有时间、记忆类型或上下文预算排序；用户不能编辑、确认或删除单条记忆。

## 决策

1. **记忆分两层**：
   - `semantic`：身份、偏好、职业等稳定语义记忆。
   - `episodic`：用户明确要求记住的任务、时间、项目事件等情景记忆。
   `working` 是生成前的运行时窗口，不单独落盘。
2. **生命周期默认安全**：
   - 显式“记住……”直接 `confirmed`。
   - 从身份/偏好/工作等句式推断的候选为 `pending`，不参与召回和 prompt 注入。
   - 用户可确认、忽略、编辑、删除；忽略和删除物理移除，不保留隐藏画像。
3. **保留加密 SQLite 整包底座**：IOS-18 第一阶段继续保存 AES-GCM combined payload，不引入敏感明文列或向量索引；规模上限保持 200 条。
4. **混合召回是确定性本地打分**：
   - 本地字符/词特征 overlap 提供词汇相关性；
   - `lastSeenAt` 时间衰减提供近期偏好；
   - semantic / episodic 类型权重提供用途排序；
   - 不引入云端 embedding，也不把 query 发送到网络。
5. **工作记忆预算显式**：召回先排序，再按条数和字符预算装箱；没有词汇匹配时回退最近 confirmed 记忆，保证跨会话连续性但不超过预算。
6. **Prompt 注入带边界**：只注入 confirmed 记忆，标注 semantic/episodic，说明“仅供个性化回答”；检索结果仍独立展示来源。

## 结果

该方案在不引入云端服务、外部向量库或明文数据库列的前提下完成 IOS-18 生命周期与召回闭环。代价是本地字符特征不能理解深层同义关系；当真实语料暴露召回不足时，再评审设备端 embedding 模型和加密索引，不影响当前 API 和安全边界。
