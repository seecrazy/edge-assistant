# ADR 0005: 应用内模型商店（开源模型下载部署）

## 状态

已接受

## 背景

产品方向更新：仅靠 install-time 自带模型不够，用户需要在 App 内浏览可安装的开源端侧大模型列表，选择后自动下载并部署，下载后立即可用；后续支持删除和换装其他模型。

这与 ADR 0002 中“拒绝首次启动强制下载”不冲突：**自带模型仍是开箱默认**（保证首启可用），模型商店是**用户主动触发的附加分发渠道**，用于换装更大/更小/更新的开源模型。

## 决策

1. App 内置“模型商店”：静态目录（catalog）列出经过筛选的开源模型（真实元数据：来源仓库、格式、参数量、体积、许可证、能力标签）。
2. 下载走 HTTPS 直连模型仓库（MVP 用 HuggingFace resolve 端点），支持进度、取消、断点续传式文件复用；每文件可选 SHA-256/大小校验。
3. 安装落盘到 `Application Support/EdgeAssistant/models/<model-id>/`，写入 metadata.json 快照；删除即删目录。
4. 激活 = 从 metadata 构建 `ModelAsset` → `InferenceEngine.load`，与自带模型共用同一引擎契约；切换模型即切换资产。
5. 真实推理依赖 IOS-13（MLX 后端）：商店先落地下载/管理/激活链路，后端接入后下载的模型即可真跑，无需改动商店层。

## 备选方案

### 方案 A：仅自带，不做商店

缺点：无法满足用户换装模型的产品需求；更新模型必须发版。

### 方案 B：应用内商店 + 自带默认（已选择）

优点：首启体验与商店灵活性兼得；模型独立于发版迭代。
缺点：需要下载管理、校验、存储管理；大文件下载耗流量（需显式进度与确认）。

### 方案 C：商店作为唯一分发（取消自带）

缺点：违背“打开即可聊天”，重新引入 ADR 0002 已否决的问题。

## 结果

选择方案 B。

### 负面影响与缓解

- 大文件下载：仅 WiFi 建议 + 明确进度 + 可取消。
- 仓库可用性（HF 直连）：目录中保留仓库地址，后续可加镜像源字段。
- 下载的模型在 IOS-13 前不能真实推理：UI 明确标注“需推理后端（待接入）”，不伪装能力。
