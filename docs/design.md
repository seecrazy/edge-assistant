# Edge Assistant Design

## 1. 背景与定位

Edge Assistant 是一个“端侧优先”的移动 AI 助手。它希望提供类似豆包的核心体验——文字聊天、语音通话、摄像头/屏幕理解——但默认不依赖云端大模型，用户语音、图像、记忆和会话数据不出设备。

第一阶段的工程目标不是复刻云端大模型的通用智力，而是验证一个可交付的端侧产品形态：

- 在中高端手机上可稳定运行本地量化模型。
- 在受限场景中提供可预期、可打断的实时语音体验。
- 用关键帧 + 语义压缩的方式实现“AI 看画面”，避免逐帧视频理解。
- 建立清晰的机型分级、模型资产分发和降级策略。

当前仓库包含完整设计文档、一个无第三方依赖的浏览器原型，以及 M1 阶段的推理抽象与模型资产领域层。原型用于验证交互状态机、机型分级、延迟预算、资产校验与回滚，不包含真实模型推理、真实电话能力和摄像头采集。

## 2. 目标与非目标

### 2.1 目标

1. **本地优先**
   - 核心对话、语音通话、视觉问答默认离线可用。
   - 不向服务端发送音频、图像、屏幕内容、联系人、日历等用户数据。
   - 用户可以查看、导出、删除本地数据。

2. **实时体验**
   - 语音端到端响应目标：P50 < 1.2s，P90 < 1.8s。
   - 支持全双工打断：用户开口后立即停止 TTS、丢弃未播音频、取消未完成推理。
   - 连续通话 10 分钟后可主动进入低功耗模式，避免温控降频。

3. **机型分级**
   - 根据内存、NPU、温控能力自动选择模型档位。
   - 低端设备不强行运行超出硬件能力的大模型。
   - 安装包通过平台资产分发机制按机型交付模型。

4. **可验证的产品边界**
   - 每个功能有明确的权限、降级和错误路径。
   - 对“能做什么 / 不能做什么”保持透明，不伪装成云端模型能力。

### 2.2 非目标

1. **不做云端兜底作为默认能力**
   - 云端能力未来可以作为显式开关，但第一版不实现。
   - 不默认上传上下文，不做“静默混合云”。

2. **不接入运营商电话网络**
   - 第一版只做 App 内实时语音/视频通话。
   - 真实电话场景仅作为后续 Android 通话助手能力评估，不作为 MVP 承诺。

3. **不追求逐帧视频理解**
   - 视觉链路采用关键帧抽取、OCR、物体检测和 VLM 语义压缩，而不是连续视频帧逐帧推理。

4. **不在当前原型中内置真实模型**
   - 当前原型是架构与交互验证，不提供真实 3B/2B/1B 模型文件。
   - 真实模型接入属于 M1 阶段工作。

## 3. 用户与场景

### 3.1 目标用户

- 对隐私敏感、不希望语音和摄像头内容上传的用户。
- 经常处于弱网或离线环境的用户。
- 需要快速、短反馈的助手场景：日程、提醒、备忘、翻译、画面解释、简单问答。

### 3.2 核心用户流程

#### A. 文字对话

1. 用户打开 App。
2. App 启动本地推理引擎并加载模型。
3. 用户输入问题。
4. 系统检索本地记忆/文档，构造短上下文。
5. 模型流式生成，UI 逐字渲染。
6. 会话写入本地加密数据库。

#### B. App 内语音通话

1. 用户点击“开始通话”。
2. 系统启动麦克风、AEC、VAD 和流式 ASR。
3. 用户说话，系统实时识别。
4. VAD 判断用户说完后，LLM 开始流式生成。
5. 首个可播片段生成后，TTS 开始流式合成并播放。
6. 用户可随时打断；系统立即停止播放并回到监听态。

#### C. 摄像头/屏幕理解

1. 用户开启摄像头或屏幕共享。
2. 系统检测画面变化，按 1–2fps 或事件触发抽取关键帧。
3. 端侧 VLM 生成画面描述；OCR 和专用小模型补充文本、物体、场景信息。
4. 系统将语义摘要压缩进对话上下文。
5. 用户语音或文字提问，助手基于摘要回答。

#### D. 本地记忆管理

1. 用户进入“隐私中心”。
2. 查看记忆、会话、权限、模型资产。
3. 删除单条记忆、某个会话或全部数据。
4. 系统同步清理向量索引和关联缓存。

#### E. 安装即内置：模型自动装载

1. 用户从应用商店安装 App；当前档位的量化模型通过 install-time asset pack 随 App **在系统安装阶段一并写入设备**，不产生独立的“安装模型”步骤。
2. 首次启动，App 自动执行：读取自带资产 → 校验 SHA-256 → 激活资产 → 装载推理引擎。全程无用户操作、无网络请求。
3. 装载过程以状态形式展示（“校验中 → 已就绪”），不阻塞非推理 UI，也不要求用户点击任何按钮。
4. 正常情况下用户感知为“打开即可聊天”：文字对话直接调用内置模型，无任何安装、下载或确认步骤。
5. 校验失败（如资产损坏）时展示错误并提供“重新校验”入口；存储不足在系统安装阶段就会被 OS 拒绝，不属于 App 内错误路径。
6. 后续模型热更新走 §4.3 的后台更新通道，与首次装载共用同一校验与回滚机制。

## 4. 总体架构

```text
┌──────────────────────────────────────────────┐
│ UI：聊天 / 语音通话 / 视频理解 / 隐私中心          │
├──────────────────────────────────────────────┤
│ 会话编排层：状态机、打断、流式调度、工具调用、RAG   │
├───────────────┬──────────────┬───────────────┤
│ LLM 推理引擎    │ 多模态管线      │ 音频/通信层      │
│ 量化模型        │ ASR/TTS/VAD   │ AEC/播放/摄像头  │
│ NPU/GPU/CPU    │ VLM/OCR/检测   │ 本地流处理       │
├───────────────┴──────────────┴───────────────┤
│ 数据层：加密 SQLite + 向量库 + 模型资产仓库         │
└──────────────────────────────────────────────┘
```

### 4.1 模块职责

| 模块 | 职责 | 关键接口 |
|---|---|---|
| UI 层 | 呈现聊天、通话、视频、隐私设置 | 纯渲染，不直接持有推理状态 |
| Conversation Orchestrator | 管理状态机、上下文、工具调用、打断 | `startCall`, `stopCall`, `interrupt`, `submitText` |
| Inference Engine | 统一封装平台推理后端、生命周期、能力门控、流式输出和取消 | `load`, `unload`, `status`, `generateStream` |
| Model Registry | 管理模型版本、hash、能力标签、档位选择、安装校验和回滚 | `register`, `resolveForDevice`, `verifyModelAsset`, `install`, `rollback` |
| Asset Installer | 自带资产目录 + 自动装载编排：校验、激活、进度上报，启动即执行 | `createBundledAssetCatalog`, `installForTier` |
| Audio Pipeline | AEC、VAD、ASR、TTS、播放 | `startMic`, `streamASR`, `speakStream`, `stopSpeaking` |
| Vision Pipeline | 关键帧、OCR、检测、VLM 摘要 | `captureKeyFrame`, `describeScene` |
| Memory Store | 本地记忆、向量检索、删除 | `remember`, `search`, `forget` |
| Privacy Center | 权限、数据审计、删除 | `audit`, `export`, `deleteAll` |

### 4.2 模型分级

| 档位 | 判定条件 | 模型 | 目标能力 |
|---|---|---|---|
| Flagship | RAM ≥ 12GB，有 NPU | 3–4B，4-bit，约 2–2.5GB | 文字、语音通话、视频理解 |
| Mainstream | RAM ≥ 8GB | 1.5–2B，4-bit，约 1–1.5GB | 文字、语音通话、基础视觉摘要 |
| Entry | RAM < 8GB | 1B，4-bit，约 0.7–0.9GB | 文字和基础语音短句，视频功能禁用或强降级 |

### 4.3 模型资产分发

- **Android**：使用 Play Asset Delivery 的 install-time 或 fast-follow asset pack，避免模型进入主 APK。
- **iOS**：使用 On-Demand Resources，首次启动完成下载、校验和装载。
- **安装即内置**：默认交付方式为 install-time asset pack（Android）/ 安装阶段随包写入（iOS 等价机制），模型在系统安装 App 时落盘，App 自带当前档位模型；首次启动的自动装载流程见 §3.2 流程 E，全程无网络请求、无用户操作。
- **完整性校验**：模型文件带版本号、hash、能力清单。
- **热更新**：允许后台下载新版本，但安装前必须完成 hash 校验，失败自动回滚。
- **低端机策略**：不安装超出档位的大模型；默认下载更小模型或提示功能受限。
- **应用内模型商店**（ADR 0005）：自带模型保持开箱默认之外，App 内提供开源端侧模型列表（真实元数据 + 许可证），用户选择后自动下载、校验、部署激活；支持删除与换装。下载为用户显式触发，进度可见、可取消。实现细节见 `docs/design-ios.md` §5.2。
- **自动装载实现契约**：启动时编排器从“自带资产目录”按设备档位选择唯一资产，依次执行 SHA-256 校验 → 激活 → 引擎装载；任一步失败都不能进入 ready 状态，且不得改变已激活资产。存储空间由 OS 在安装阶段保证，App 内不做安装时存储检查；编排器保留可选的防御性检查位。

### 4.4 M1 参考实现边界

当前仓库中的 `prototype/js/inference-engine.js` 和 `prototype/js/model-registry.js` 是平台无关的参考实现，用于固化跨平台契约：

- `InferenceEngine` 负责 `unloaded/ready` 生命周期、模式能力门控、流式 token 输出、AbortSignal 取消和推理指标采集。
- `ModelRegistry` 负责资产元数据校验、按设备档位选择最新资产、SHA-256 完整性校验、失败安装保持当前资产，以及单步回滚。
- 浏览器原型中的“模型”是用于校验流程的占位字节，不是可推理的量化模型。
- Android 与 iOS 后端必须实现同样的生命周期和取消语义；平台差异只允许存在于适配层内部。

接口细节见 `docs/api/inference-engine.md`。

## 5. 关键交互设计

### 5.1 语音通话状态机

```text
idle
  ├─ start_call → listening
  └─ submit_text → thinking（文字模式复用状态机）
listening
  ├─ user_stop → thinking
  ├─ interrupt → listening（忽略无效打断）
  └─ stop_call → idle
thinking
  ├─ first_token → speaking
  ├─ interrupt → listening（取消未完成推理）
  ├─ stop_call → idle
  └─ error → idle
speaking
  ├─ tts_done → listening
  ├─ interrupt → listening（停播、丢帧、取消未完成推理）
  ├─ stop_call → idle
  └─ error → idle
```

打断规则：

1. VAD 检测到用户开口。
2. 立即停止 TTS 播放。
3. 丢弃未播放的音频块。
4. 取消尚未完成的 LLM 推理（`speaking` 阶段首 token 后流式输出通常仍在进行，同样必须取消）。
5. 状态回到 `listening`，避免旧回复污染下一轮。

状态机不设置 `thinking_cancel` 等中间态：打断清理是副作用而不是独立状态，进入 `listening` 前必须同步完成停播、丢帧和取消。

### 5.2 延迟预算

| 链路 | VAD | ASR | LLM 首响应 | TTS 首包 | 总计 |
|---|---:|---:|---:|---:|---:|
| Flagship 语音 | 80ms | 200ms | 350ms | 120ms | 750ms |
| Mainstream 语音 | 80ms | 200ms | 500ms | 120ms | 900ms |
| Entry 语音 | 80ms | 220ms | 700ms | 140ms | 1140ms |

预算是目标值，不是承诺值。真实实现必须以设备实测为准，并在温控、电量、后台模式下动态调整。

### 5.3 视频理解策略

- 不逐帧理解，按场景变化抽取关键帧。
- 关键帧进入 VLM 后输出短摘要。
- OCR 和物体检测使用小型专用模型，降低算力压力。
- 每次视觉上下文保留有限长度，超过后滚动淘汰。
- 摄像头画面不持久化，除非用户显式保存。

### 5.4 小模型能力补偿

1. **场景收窄**：语音模式限制回复长度，优先短句。
2. **本地 RAG**：检索用户文档、备忘和历史记忆，减少模型自由发挥。
3. **工具调用**：日程、提醒、计时、查词等任务走确定性工具。
4. **受约束解码**：通话模式限制输出风格、长度和可用话术模板。
5. **高频音频缓存**：常用短句预生成 TTS，降低首包延迟。

### 5.5 上下文管理

小模型可用上下文有限，上下文必须按模式显式分配预算，而不是把所有历史塞进 prompt：

| 模式 | 上下文预算（目标值，待 M1 实测校准） | 构成 |
|---|---:|---|
| chat | 4K tokens | system + 检索记忆片段 + 最近 8 轮对话 |
| voice | 2K tokens | system + 当前轮检索片段 + 最近 3 轮对话 |
| video | 4K tokens | system + 视觉摘要区 + 最近 6 轮对话 |

构造规则：

1. System prompt 固定在最前，包含当前模式、可用工具和输出约束。
2. RAG 检索片段按相关度插入，每片带来源标签，方便模型区分记忆和对话。
3. 超出预算时，从最旧的中间轮次开始淘汰，永远保留 system 和最近 N 轮。
4. 被淘汰的轮次不丢失：仍保存在会话数据库中，只是不再进入模型上下文。
5. 视觉摘要区独立于对话轮次，按 5.3 的滚动淘汰策略管理。

### 5.6 工具调用设计

第一版提供以下确定性工具，全部本地执行：

| 工具 | 用途 | 所需权限 |
|---|---|---|
| `create_reminder` | 创建提醒 | 通知 |
| `create_timer` | 设置计时 | 无 |
| `query_calendar` | 查询日程 | 日历 |
| `create_calendar_event` | 创建日程 | 日历 |
| `lookup_contact` | 查询联系人 | 通讯录 |
| `dictionary_lookup` | 查词 | 无 |

调用流程：

1. 模型输出结构化工具调用意图，编排层解析并校验参数。
2. 编排层检查 `tool_grants`：未授权工具直接拒绝，并在回复中说明原因。
3. 首次调用需要授权的工具时，前台弹出授权框，结果写入 `tool_grants`。
4. 工具执行结果以 `tool` 角色消息注入上下文，供模型组织回复。
5. 工具失败时返回结构化错误，模型只能转述失败原因，不得编造结果。

约束：

- 工具调用不经过网络，结果不缓存到模型上下文之外。
- 用户可以随时在隐私中心按工具粒度撤销授权。

### 5.7 温控与低功耗降级

设备热状态分为四级，状态由系统热 API 与连续推理时长共同驱动，带迟滞避免抖动：

| 状态 | 进入条件 | 降级动作 |
|---|---|---|
| normal | 默认 | 无 |
| warm | 系统热警告或连续通话 ≥ 10 分钟 | 缩短回复长度上限；视觉抽帧 1–2fps → 0.5fps |
| hot | 系统严重热警告 | 停用视觉管线；语音回复进一步缩短；关闭高频 TTS 缓存 |
| critical | 系统临界热警告 | 暂停推理，提示用户设备过热，保留文字输入 |

恢复规则：状态只按 `critical → hot → warm → normal` 逐级恢复，每级至少停留 60 秒。

降级必须是可预期的：每次降级在 UI 上提示一次当前能力变化，恢复后同样提示。降级事件写入本地指标，不上传。

## 6. 数据与状态模型

```sql
sessions(
  id TEXT PRIMARY KEY,
  mode TEXT NOT NULL,       -- chat | voice | video
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL,
  title TEXT
)

messages(
  id TEXT PRIMARY KEY,
  session_id TEXT NOT NULL,
  role TEXT NOT NULL,       -- user | assistant | system | tool
  content TEXT NOT NULL,
  created_at INTEGER NOT NULL,
  metadata_json TEXT
)

memories(
  id TEXT PRIMARY KEY,
  content TEXT NOT NULL,
  embedding BLOB,
  source TEXT NOT NULL,
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL
)

model_assets(
  id TEXT PRIMARY KEY,
  tier TEXT NOT NULL,
  version TEXT NOT NULL,
  sha256 TEXT NOT NULL,
  size_bytes INTEGER NOT NULL,
  capabilities_json TEXT NOT NULL
)

tool_grants(
  tool_name TEXT PRIMARY KEY,
  granted INTEGER NOT NULL,
  updated_at INTEGER NOT NULL
)

call_logs(
  id TEXT PRIMARY KEY,
  session_id TEXT NOT NULL,
  started_at INTEGER NOT NULL,
  ended_at INTEGER,
  duration_ms INTEGER,
  interrupted_count INTEGER NOT NULL DEFAULT 0
)
```

### 6.1 本地数据原则

- 数据库文件加密，密钥存放在系统安全存储区。
- 向量索引与主数据库同生命周期，删除记忆时同步删除向量。
- 音频和视觉中间数据优先内存处理，不落盘。
- 会话日志默认本地保留，用户可配置自动清理周期。

## 7. 权限与隐私

| 权限 | 用途 | 拒绝后的表现 |
|---|---|---|
| 麦克风 | 语音通话、语音输入 | 仅文字模式可用 |
| 摄像头 | 视觉问答 | 视频功能禁用 |
| 屏幕录制 | 屏幕理解 | 屏幕理解禁用 |
| 通讯录 | 用户显式查询联系人 | 相关工具不可用 |
| 日历 | 日程管理 | 相关工具不可用 |
| 通知 | 提醒 | 提醒功能降级 |

隐私承诺：

1. 默认无网络请求。
2. 不上传音频、图像、屏幕内容、记忆或会话。
3. 权限使用在前台明确可见。
4. 删除操作必须清理数据库、向量索引、缓存和模型派生数据。

### 7.1 数据导出

- 导出内容为用户主动选择的数据：会话（含消息）、记忆、模型资产清单；不含模型文件和派生缓存。
- 导出格式为单个 JSON 文件，带 schema 版本号，方便未来导入。
- 导出必须显式触发、显式确认目标位置；导出文件不含加密，离开设备后不再受本产品保护，导出前必须向用户说明。
- 导出过程不经过网络，由系统分享面板完成。

### 7.2 安全设计

1. 数据库使用 SQLCipher（或平台等价方案）全库加密，密钥为 256 位随机值。
2. 密钥存放在 iOS Keychain / Android Keystore，不落入 App 沙盒普通文件。
3. 向量索引与主数据库使用同一密钥体系，删除记忆时密文索引同步删除。
4. 本地日志不记录用户消息原文，只记录事件类型与指标。
5. 隐私中心提供“抹掉全部数据”入口：删除密钥 + 删除数据库 + 删除缓存，密钥销毁后历史数据不可恢复。

## 8. 边界与错误处理

| 场景 | 处理 |
|---|---|
| 模型文件损坏 | hash 校验失败，切换内置极小兜底模型并后台重下 |
| 设备过热 | 降低视觉帧率、缩短上下文、切换低功耗回复模板 |
| 内存不足 | 释放视觉模型，仅保留语音/文字 |
| 麦克风权限被拒绝 | 禁用语音通话，提供文字入口 |
| 摄像头权限被拒绝 | 禁用视频理解，不影响语音 |
| ASR 低置信度 | 请求用户重复或展示候选文本 |
| TTS 被打断 | 立即停播、丢帧、取消未完成推理 |
| 工具调用失败 | 明确告知失败原因，不编造结果 |
| 本地能力不足 | 明确提示当前档位限制，不假装云端能力 |
| 模型装载失败 | 引擎回到 `unloaded`，提示重新校验安装；安装失败路径见 4.3 |
| 自动装载校验失败 | 保留当前状态（含已激活资产），提供“重新校验”入口；记录本地指标 |
| 存储空间不足以安装 App | 由应用商店/OS 在安装阶段拒绝，App 内不处理 |
| 存储空间不足 | 阻止模型更新与新记忆写入，提示清理空间；不自动删除用户数据 |
| 向量索引损坏 | 自动重建索引；重建期间 RAG 降级为关键词检索，不中断对话 |

## 10. 开放问题

1. iOS 上 Speech Framework 与本地 ASR 的准确率、功耗、延迟对比需要实测。
2. 3B 模型在主流 Android NPU 上的兼容性和首 token 延迟需要基准测试。
3. 视频模式中 VLM 与主 LLM 的内存峰值共存策略需要平台实测。
4. Android 真实电话助手能力受系统版本和厂商差异影响，需要单独评估。
5. 5.5 中各模式上下文预算为工程估计，需要用目标设备实测最小可用值后校准。
6. 多语言场景下端侧 ASR/TTS 的模型体积与延迟需要评估，可能需要按语言分发附加资产。
